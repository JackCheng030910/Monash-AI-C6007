Task 1 代码深度解析与设计思路（Deep Dive）

整个 Task 1 的核心解题思想可总结为：“校验拦截在前，关联映射在中，逻辑判定在后，格式输出收尾”。下面结合具体的实现考点进行深度拆解：

1. 模块导入与标准错误流输出 (import sys)

题目要求在遇到非法数据记录（Invalid Records）时向标准错误流输出警告，而不是直接报错终止程序。Python 默认的 print() 是输出到标准输出流 (stdout)，因此我们需要导入 sys 模块，并在调用时加上 file=sys.stderr 参数：

import sys
# 示范：将警告信息定向输出到标准错误流，避免打断正常程序执行
print(f'Warning: Package {p_id} has invalid weight ({weight}).', file=sys.stderr)

2. 数据读取与边界校验 (Steps 1 & 2: Reading & Validation)

在数据读取阶段，我们使用了对齐列表（Aligned Lists）的数据结构，即不同属性存放在不同列表中，通过相同的索引 $i$ 互相映射。解题逻辑分为以下关键点：

  • 跳过表头与格式化解析： 使用 readlines()[1:] 切片避开 CSV 第一行的列名，并通过 .strip().split(',') 去除换行符并切分成数据数组。同时将字符串正确强转为对应的类型（如 int(battery)、float(load)）。
  • 严格的条件校验 (Guards & Skip): 每读取一行数据，都设置多重 if 检查。只要有任意一项校验未通过，立即通过 print(..., file=sys.stderr) 报出 Warning，并配合 continue 跳过当前行，确保只有 100% 合规的数据才能追加（.append()）到列表中：
    • read_robots：校验电池电量范围 0 <= battery <= 100、载重 load >= 0、区域必须为非空且纯大写字母（zone.isalpha() and zone.isupper()）。
    • read_destinations：校验目的地区域代码是否全大写。
    • read_packages：校验包裹重量是否非负 (weight >= 0)。
  • 交叉引用校验 (Cross-referencing): 在 read_tasks 函数中，我们需要额外的参数 destination_ids 和 package_ids。这是因为任务中的起点 s_id、终点 target_id 以及包裹 p_id 必须是前面已经通过校验的合法 ID。如果不在合规列表中（s_id not in destination_ids），则直接判为非法 Task 并跳过。

3. 核心算法：任务可行性判定 (Step 3: is_task_executable)

这个函数是整个 Task 1 的判定大脑，逻辑非常严密，主要分为四大步骤：

  1. 定位任务索引 (Task Lookup)： 确认输入的 task_id 是否存在。若存在，通过 task_ids.index(task_id) 获取当前任务在列表中的索引 t_idx，并顺藤摸瓜提取出该任务的起点 ID (s_id)、终点 ID (t_id) 和包裹 ID (p_id)。
  2. 获取区域与重量属性 (Attribute Mapping)： 利用 destination_ids.index(s_id) 和 .index(t_id) 查出起点与终点所在的区域名称 (source_zone 和 target_zone)；利用 package_ids.index(p_id) 查出当前包裹的实际重量 (pkg_weight)。
  3. 机器人能力匹配遍历 (Robot Matching)： 使用 for i in range(len(robot_ids)) 逐个检查可用的机器人。要成功执行任务，必须同时满足以下三个硬性条件： 
    # 条件 1: 机器人当前区域必须与任务起点区域一致
# 条件 2: 机器人当前区域必须与任务终点区域一致（即起点终点需在同一区域）
# 条件 3: 机器人的最大载重量必须大于或等于包裹重量
if r_zone == source_zone and r_zone == target_zone and r_load >= pkg_weight:
    return True # 只要找到任意一台符合条件的机器人，立刻返回 True 终止循环
  4. 默认失败返回： 如果循环遍历完所有机器人都无法满足上述条件，说明没有机器人能胜任，最终返回 False。

4. 报告生成与主函数整合 (Step 4: Report & main)
  • 写入报告 (write_feasability_report): 使用 open(file_path, 'w') 以覆盖写入模式打开文件。使用 for 循环同时读取任务 ID 和对应的布尔值结果，根据布尔值累加 executable_count 与 non_executable_count 计数器，格式化写入每行状态（如 T1: executable），最后在文件末尾输出统计汇总，并调用 .close() 释放资源。
  • 主入口依赖顺序 (main Execution Order): 在 main() 函数中，执行顺序至关重要：必须先调用 read_destinations 和 read_packages 获取合规 ID 列表，然后再调用 read_tasks 进行交叉验证。拿到所有清洗后的数据后，遍历任务列表收集判定结果，最后统一传给 write_feasability_report 输出文件。
  • 程序入口保护 (if __name__ == "__main__":): 将测试调用的 main(...) 放在脚本入口保护块中，这样既方便我们自己本地运行测试，又能保证提交给自动评分脚本 (Auto-grader) 导入时不会触发意外执行。

Assignment 3 - Task 1 核心攻略与解析（k-gram 语言模型构建）

题目背景与核心目标：

数字诗歌工作室（Digital Poetry Studio）希望开发一个简易的诗歌生成器。Task 1 的目标是实现系统的文本读取清洗、诗歌切分、Token 化以及 k-gram N-gram 频率模型的统计构建，为后续 Task 2 的生成奠定数据基础。

Task 1 规格与功能要求（Specification）：

Step 1: Text Preprocessing & Cleaning
- read_text(file_path): 
  读取文本文件。需拦截 FileNotFoundError；若去除空格后文本为空，抛出 ValueError。
- clean_text(text): 
  将文本转为小写，并清除除逗号 (,) 和句号 (.) 之外的所有标点符号。若输入非字符串，抛出 TypeError。

Step 2: Build k-gram Model
- build_kgram_model(text, k):
  1. 校验输入合法性（k 为正整数且非 bool，text 为字符串）。
  2. 清洗文本并将逗号与句号替换为前后带空格的形式 (如 " , " 和 " . ")。
  3. 识别数字行（如 "1", "2"）作为诗歌边界，在每首诗结尾追加 "" 标识符。
  4. 遍历所有 Token，使用长度为 k 的滑动窗口统计每个 (Context) -> Next_Word 的频次，返回嵌套字典。
  5. 若无法生成任何 k-gram，抛出 ValueError。

Step 3: Query Options
- get_next_token_options(kgram, model):
  查询特定 k-gram 元组在模型中的下一个 Token 频次字典。若不存在则安全返回空字典 {}。

Step 5: Unit Testing
- 编写 unittest 单元测试，涵盖逻辑清洗、模型频次统计、诗歌边界切割、异常输入拦截以及文件读取异常。

待完成的核心任务（Implementation Tasks）：

  • read_text(file_path)：实现文本加载与文件边界防护。
  • clean_text(text)：实现保留指定标点（逗号、句号）的文本清洗。
  • build_kgram_model(text, k)：实现诗歌边界标记 <END> 追加、Token 拆分与滑动窗口建模。
  • get_next_token_options(kgram, model)：实现模型 Key 的安全检索。
  • TestKgramModel(unittest.TestCase)：实现完整的自动化单元测试集。

Task 1 代码深度解析与解题思路（Answer Breakdown）

在 Task 1 的实现中，我们的核心思维路径是：“严密校验在前，标点分离在中，边界识别在后，滑动窗口收尾”。下面结合完整实现代码，逐模块拆解解题逻辑：

1. 异常预警与文本预处理 (Step 1: read_text & clean_text)
  • 文件读取防御机制 (read_text): 使用 try...except FileNotFoundError 捕获文件缺失，并抛出自定义提示；利用 content.strip() 校验文件内容，若为空或全为空白字符则主动抛出 ValueError。
  • 保留关键标点的清洗策略 (clean_text):

    先通过 isinstance(text, str) 拦截非字符串输入。使用 Python 内置的 string.punctuation 遍历所有标点符号，通过 symbol != ',' and symbol != '.' 显式保留逗号与句号，其余标点全部使用 .replace(symbol, '') 剔除。

    # 保留逗号与句号，其余标点剔除
for symbol in string.punctuation:
    if symbol != ',' and symbol != '.':
        text = text.replace(symbol, '')

2. 核心算法：k-gram 模型构建 (Step 2: build_kgram_model)

这是整个 Task 1 最关键的逻辑部分，细分为以下四个步骤：

  1. 参数严格校验 (Type & Value Checking): 特别注意 Python 中 bool 是 int 的子类（isinstance(True, int) 为 True），因此判断 $k$ 是否为整数时，必须加上 not isinstance(k, bool)，否则无法通过单元测试拦截： 
    if not isinstance(k, int) or isinstance(k, bool):
    raise TypeError('k must be an integer')
if k <= 0:
    raise ValueError('k must be a positive integer')
  2. 标点符号独立 Token 化 (Punctuation Tokenization): 为了让逗号 ',' 和句号 '.' 能够作为独立的 Token 参与建模，在 split 之前调用： 
    cleaned_text = cleaned_text.replace(',', ' , ').replace('.', ' . ')
    这样再按换行和空格切分时，标点便能自然分离开来，与普通单词地位一致。
  3. 诗歌边界识别与 <END> 标记追加 (Poem Boundaries): 逐行读取切分后的文本。利用 line.isdigit() 识别数字编号行（代表一首新诗的开始）。在遇到新编号或遍历结束时，只要当前 Token 列表中有内容且尾部不是 <END>，就主动追加一个 <END>，精确隔离不同诗篇之间的上下文连贯性。
  4. 滑动窗口统计频次 (Sliding Window & Nested Dict): 遍历 Token 数组，窗口长度为 $k+1$。前 $k$ 个 Token 转换成可哈希的 **Tuple 元组** 作为字典的键（Context），第 $k+1$ 个 Token 作为预测值（Next Word）。 
    for i in range(len(tokens) - k):
    current_kgram = tuple(tokens[i:i+k])
    next_word = tokens[i+k]
    
    if current_kgram not in kgram_model:
        kgram_model[current_kgram] = {}

    kgram_model[current_kgram][next_word] = kgram_model[current_kgram].get(next_word, 0) + 1

3. 模型安全查询 (Step 3: get_next_token_options)

查询逻辑极为干净简洁：优先检查输入的 kgram 是否存在于字典 model 中。若存在直接返回对应的下一个 Token 频率字典；若查询不到（未匹配的上下文），则安全返回空字典 {}，避免引发 KeyNotFound 报错。


4. 自动化单元测试设计 (Step 5: unittest Suite)

在测试模块 TestKgramModel 中，我们对整个流程进行了全方位的单元测试覆盖：

  • test_clean_text_logic：验证大写转小写以及特殊标点保留（如 "HELLO! 'World': sings," $\rightarrow$ "hello world sings,"）。
  • test_build_model_basic：测试基础频次累加逻辑（如重复的 "a b c" 能否将 ('a', 'b') 对应的 'c' 频次累加至 2）。
  • test_numbered_poems_and_punctuation：验证数字编号分诗以及 <END> 标记的嵌入位置是否完全准确。
  • test_invalid_inputs：使用 with self.assertRaises(...) 校验传入布尔值 $k$、负数 $k$、非字符串 text 或 Token 长度小于 $k$ 时能否准确引发异常。
  • test_file_errors：结合 tempfile.NamedTemporaryFile 模拟临时空白文件，测试边界异常触发。
